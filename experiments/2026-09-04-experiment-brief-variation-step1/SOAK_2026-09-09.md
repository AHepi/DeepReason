## §2 — A3 refused first, and the refusal was the tranche's own documented one

A3 exited 1 in two seconds on the first invocation:

    SystemExit: ARM RIG REFUSED: arm A3 needs 'op.neighbourhood.v1' from the
    operator plugin directory; loaded=[] notices=[]. An A3 that silently fell
    back to the shipped neighbourhood would be A0 wearing A3's label.

This is `SOAK.md`'s own failure #2, verbatim in mechanism. `cycle_soak.py`
resolves its working directory from `--out` (else a fresh temp dir) and sets
`DEEPREASON_HOME` to `<workdir>/home` inside its `main()`, which runs AFTER
`sitecustomize` has installed the arm at interpreter start; A3's rig reads the
operator plugin directory out of `DEEPREASON_HOME` before `main()` exists. So
the template was written where the arm looked and the soak looked somewhere
else.

**The finding is not the failure; it is that the committed script could not
reproduce the document's own green A3.** `SOAK.md` names the fix — *"`--out`
plus an exported home, so both agree before the interpreter starts"* — and
`soak_arms.sh` never carried it. Fixed in this tranche's runner only (one
workdir per arm, home derived the way the soak derives it, exported before the
interpreter starts, template written into that same home). Nothing sealed
moved: `armrig.py`, `sitecustomize.py`, `PREREG.md` and `PROVE_ARMS.txt` all
still verify against `SEALED.txt`.

The guard fired at cost zero before any provider call, which is what it is
for.
