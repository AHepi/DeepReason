Why this is a COST and not the F2-d defect class
------------------------------------------------
This same metric caught a real defect once (tests/test_reference_menu.py::
test_a_pre_v6_conjecture_pack_carries_no_v6_menu -- 784.5 -> 875.0 with every
epistemic metric identical, caused by a reference menu naming a field the
seat could not fill; the fixture was NOT re-pinned, the bug was fixed).
The signature here looks the same from the metric alone, so it is
distinguished from the prompt bytes rather than from the number:

  - the delta is TWO named sections, both required by R2a and R2c, and
    nothing else -- no new menu, no new handle, no field the seat cannot
    fill, no added instruction (the instruction-count guard, S6/A6, holds);
  - the repair prompt, which is where an over-eager menu would also have
    shown up, is byte-identical;
  - the six other metrics -- valid_first_attempt_rate, repair_rate,
    candidate_family_count, unique_candidate_bodies, executable_test_yield,
    verifier_backed_success_rate -- are unchanged, so the seat's behaviour
    is unchanged and only the rendering grew.
