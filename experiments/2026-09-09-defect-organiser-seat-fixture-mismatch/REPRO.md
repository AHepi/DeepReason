# Reproduction: every pinned literal is the epoch-1 attachment's

The failing gate is the symptom. The cause is demonstrated by a single
comparison, run offline against the committed tree and one git blob: for each
of the three literals the tests carry, the pinned value matches the attachment
as it stood at `9554abfe4` (epoch 1) and contradicts the attachment as it
stands now, while the attachment's own manifest and its own committed
admission proof agree with the tree.

Script (session scratchpad, not committed): reads the literals out of
`tests/test_organiser_seat.py` by regex, the digests out of
`attachment/ATTACHMENT.sha256`, the record counts out of
`attachment/CONVERSION.json`, and the block counts and legend split out of
`proof/DRY_ATTACH.txt`; it fetches the epoch-1 bytes with `git show 9554abfe4:…`.

## What it establishes

1. **The literals are not wrong-by-typo; they are correct-for-epoch-1.** All
   three pinned digests reproduce the `9554abfe4` blobs exactly. The tests
   were right when they were written.
2. **The tree is internally consistent.** `ATTACHMENT.sha256` agrees with the
   committed bytes; `CONVERSION.json`'s 12/46/36 room records plus one preamble
   per file (Amendment 4, A16) give 13/47/37, which is exactly what
   `DRY_ATTACH.txt` recorded when the tranche re-ran admission. Nothing in the
   attachment is damaged.
3. **The three published sources needed for the fix all exist and are
   regenerated by the same window that moves the attachment**
   (SPEC Amendment 4, S38 regenerates `ATTACHMENT.sha256`, S40 re-runs
   `proof/dry_attach.py`). Reading them is therefore not a workaround; it is
   reading the attachment's own account of itself.

## The mutation that would catch a regression

Reading a published value is only a test if the published value can disagree
with the code. It can: `DRY_ATTACH.txt`'s `blocks_by_file` and
`legend_shown_by_file` are the output of `admit_attachment_paths` and the
legend renderer at the time the tranche ran them. If admission stopped minting
one block per paragraph, or the legend's 32-block cap or its hash ordering
moved, the test's freshly computed dossier would stop matching the recorded
proof and the assertion would go red — which is the property the pinned
literals were there to give, now sourced from something a later window is
obliged to keep current instead of from a copy nobody is obliged to update.
