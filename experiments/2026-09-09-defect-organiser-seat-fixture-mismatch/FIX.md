# Fix: the tests read the attachment's own record of itself

Scope: `tests/test_organiser_seat.py` only. No file under `src/`,
`experiments/` or `mini/` moves. One map document gains a `Traps` entry in the
same commit (`docs/map/INV-seat-section-plugins.md`, which owns the organiser
shell and carries `check: python -m pytest tests/test_organiser_seat.py -q`).

## The principle

Three facts about the committed attachment are asserted in this file. Each is
already published by the attachment itself, in a file the tranche's own SPEC
obliges the rewriting window to regenerate. The fix replaces each copy with a
read of the published source. Nothing is deleted and no comparison is
loosened: every assertion still says "the harness, run here, produces exactly
this", and the right-hand side is now a committed record rather than a
hand-typed one.

| fact | published source | regenerated by |
|---|---|---|
| the three sha256 digests | `attachment/ATTACHMENT.sha256` (cross-checked against `attachment/CONVERSION.json`'s per-file `sha256`) | SPEC Amendment 4, S38 |
| blocks per file | `attachment/CONVERSION.json`: `files[name].records` + one `preamble` per file (A16) | S38 |
| blocks admitted, legend split, blocks withheld | `proof/DRY_ATTACH.txt` — the tranche's committed dry attach and organiser render | S40 |

No literal has to stay. The brief's fallback — point a literal at the retired
epoch-1 attachment under `runs/armR-epoch1/` — has no target: that directory
holds logs and result JSON only, and the epoch-1 attachment bytes exist
nowhere in the working tree (REPRO.md §3 of the ruled-out list).

## The changes, one by one

**F1. `PINNED` becomes `ATTACHED_DIGESTS`, read from the manifest.** A module
helper parses `ATTACHMENT.sha256` into `{name: digest}` for the three `.txt`
entries (`CONVERSION.json`'s own line is skipped). The name changes because
"pinned" is what the values stopped being; every use site follows.

**F2. `test_the_fixture_is_the_committed_attachment_byte_for_byte` gains a
second witness.** It still hashes the committed bytes and compares. It now
compares against BOTH published records — the manifest and `CONVERSION.json`'s
per-file `sha256` — and asserts the manifest names exactly the three attached
files. Three independent records must agree; a byte edited without a
regenerated manifest still fails, which is the assertion's whole job.

**F3. `test_admission_mints_one_block_per_room_record` derives its counts.**
Expected blocks per file = `CONVERSION.json`'s room-record count for that file
plus one, when that file has a preamble paragraph — which is exactly the
design claim the test's docstring makes ("a record is a paragraph is a block"),
now including the one non-record paragraph Amendment 4's A16 added and
disclosed. The derived total is additionally required to equal
`DRY_ATTACH.txt`'s admitted `blocks.paragraph` and its `blocks_by_file`, so
the live admission run, the converter's record and the tranche's proof must
all three agree.

**F4. `test_the_organiser_brief_shows_the_whole_room_and_the_directive` reads
the legend from the proof.** `by_file` is still computed from the rendered
prompt and the dossier; it is compared against `DRY_ATTACH.txt`'s
`legend_shown_by_file`. The shown total must equal the proof's `legend_shown`,
and the withheld notice is built from the proof's `legend_withheld`, which is
itself required to equal `len(dossier.blocks) - legend_shown` — so the number
in the notice is tied to the dossier under test and cannot drift into
agreement by accident.

**F5. The prose that carried the old numbers is corrected.** The module
docstring's "(12 conjectures, 46 proposals, 36 objections)" becomes the record
count plus the three preambles Amendment 4 added; the comment explaining the
hash ordering keeps its explanation and drops its 7/13/12 tally in favour of
naming the source; the `_config` comment's "~53 000 characters" becomes
~56 000 (`chars_total` 53 493 plus 2 460 of preamble).

## What would fail if the fix were wrong

The mutation that matters: if `admit_sources` stopped minting one block per
paragraph, or the legend's 32-block cap or its content-id ordering moved, the
freshly built dossier would stop matching the committed proof and F3/F4 go
red. That is the property the literals were there to give. It is verified by
the ordinary run of the file: the three tests must pass on the current
attachment, and the other nine must keep passing untouched.

## Risk accepted, stated

A future window that rewrites the attachment and does NOT re-run
`proof/dry_attach.py` will turn this file red. That is the correct outcome —
S40 requires the re-run — and it is a louder failure than the silent drift
that produced this tranche.

## Boundaries

- No assertion is deleted, and none is weakened to a `>=`, an `in`, or a
  `pytest.approx`.
- `src/` is untouched, so no gate obligation arises from code; the full gate
  is run once anyway as the goal's second success criterion.
- Frozen surfaces: none in contact.
