# PopperSemantics / Open Inquiry hardening package

## Main documents

[PopperSemanticsV1_1.md](PopperSemanticsV1_1.md) is the proposed semantic authority. It preserves the explanatory-universality target and the recursive, nonprocedural kernel. It adds contribution-specific authorship and an explicit refinement contract. Its achievement-sensitive interpretation of universal creative inquiry is an identified substantive modeling commitment.

[Open_Inquiry_Specification_1_1.md](Open_Inquiry_Specification_1_1.md) is the subordinate staged specification. It separates semantic claims from recorded evidence and finite checks, repairs the event and dependency contracts, and lays out development gates toward implementation.

[Hardening_Audit.md](Hardening_Audit.md) explains the findings, original source locations, changes, and verification limits. Neither the audit nor the proposed replacements asserts that a new authority has already been accepted by the user.

## Working reference and evidence

The `verification` directory contains a small standard-library reference checker, 66 tests, two grounded fixture generators, a mutation runner, and the actual run results. [Verification_Report.md](verification/Verification_Report.md) states the coverage and limitations. This is a finite bookkeeping reference, not a semantic creativity classifier or a universal inquiry implementation.

Run the tests from that directory with `python -m unittest -v`. Run `python build_reports.py` to regenerate the complete finite verification evidence. Python 3.10 or later is required by the code's syntax; no third-party packages are required. The report identifies the version actually used for the delivered run.

## Version and source handling

The original uploads are unchanged and are not duplicated in this package. The three source books are not redistributed. `manifest.json` records original target-file hashes and hashes of the delivered artifacts, excluding the manifest itself. A digest identifies the exact bytes reviewed or delivered; it is not an epistemic certificate.

The replacement specification is bound to the replacement authority. Adopting only one replacement while retaining an older companion requires an explicit compatibility review rather than silently mixing versions.
