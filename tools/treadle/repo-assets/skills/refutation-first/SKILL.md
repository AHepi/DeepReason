# Refutation First (Warp W3)

<!-- PROMPT-CORE-BEGIN -->
Before any claim receives proof effort, attack it.

1. Declare the budget first: which zoo members, what random-structure
   bounds, how many candidates, what time. The budget is frozen before
   the attack starts.
2. Attack: evaluate the claim over every in-budget structure via the
   twin. Any FAIL is a candidate countermodel: certify it (member
   certificate) before arguing about it.
3. Survival is recorded as SURVIVED_DECLARED_ATTEMPT with the exact
   budget. Survival is never confirmation and never raises the claim's
   status by itself.
4. A found countermodel may be rejected ONLY by citing a frozen
   variation criterion it violates, or by filing an amendment that adds
   the criterion - stating plainly that the class is being narrowed in
   response to this countermodel. Silent rejection is prohibited;
   informal "that model doesn't count" is monster-barring and must
   become a frozen criterion or an accepted refutation.
5. If the claim survives, hand off to discharge with the attack record
   attached; the prover works knowing exactly what was already tried.
